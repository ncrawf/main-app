## §2 — Object model (candidate; names → C5; composes §B + registry `101`/`102`/`106`/`217`)
- **`agent_definition`** — stable identity/purpose: name·version · owner · intended workflow lanes · allowed principals · **authority ceiling** · lifecycle/deprecation. (Not the model.)
- **`agent_runtime_profile`** — versioned operational passport: model route · harness version · context policy · **skill-catalog projection** · tool/capability grants · credential policy · memory policy · delegation policy · execution environment · HITL/steering mode · token/cost/latency budgets · trace/eval policy · fallback/rollback/kill-switch. (= registry `agent_runtime_profile` 101/102.)
- **`agent_session`** — continuity with a particular user/operator/task.
- **`agent_run`** — one execution attempt. **Separate (no schema at this gate — §G2C.4/§G2C.8 Knox-patch 8):** (i) **stable run identity**; (ii) **append-only immutable execution events / evidence** (never rewritten); (iii) **evolving operational run status** (may advance · suspend · fail · cancel · complete); (iv) an optional **derived current-status projection**. "A run is data" holds for the events/evidence; the *live status* is not frozen while progressing. (`agent_rollout` = the eval unit.)
- **`subagent_run`** — a delegated child with **narrower** authority + context (§7).
- **Law (registry `106`):** *an agent is the **model + a governed harness** (context·tools·memory·skills·sandbox·identity·HITL·trace·domain-boundaries).* **The harness is where authority constraints are enforced, narrowed, recorded and evidenced — NOT where authority originates** (Knox-patch 1). Authority **originates** in principal/tenant grants · owning-domain + capability/action contracts · consent/processing authority · mission purpose · policy · jurisdiction. **Current object state CONSTRAINS the applicability of authority (enable/prohibit/narrow) — it is not itself a source** (Knox-patch E). And **context inclusion does not preauthorize action** — effective permission is re-evaluated at every consequential tool call / external effect / commit boundary (§G2C.4-PoC). Model choice is downstream of workload architecture; model selection is OMNI's, not a user-facing "which AI is right" marketplace.
- **G2-consumption note (detail → §G2C.2):** the `agent_definition` authority ceiling is **one constraint among many** and **never originates or overrides** authority; **effective permission is the INTERSECTION / meet** of `actor grant ∩ mission contract ∩ capability/action envelope ∩ object/unit admissibility ∩ purpose ∩ tenant/principal scope ∩ consent/processing authority ∩ jurisdiction/policy ∩ current validity` — **denial/prohibition dominates where applicable; no total ordering, no scalar "minimum"** (G2 rejected total orders; Knox-patch 2). The `agent_runtime_profile` fields **reference, they do not redefine**, the G2 constitution — `context policy` binds to the Context Router draw (S6); `memory policy` governs **runtime-owned memory copies only** (memory-kind discipline, §G2C.3) and carries **no durable-knowledge authority**; add profile bindings for admissible **authority-profile envelope · currency/freshness requirement · `consequence_class` · `promotion_ceiling` (default propose-only for S2/S3) · revocation/invalidation response**. **There is NO runtime-owned durable reusable-knowledge store** — anything that would hold reusable knowledge is an S2 reservoir (governed, admission-gated, owned), never an agent-memory object.

## §3 — Context budget · health · compaction · rehydration (the screenshot's lesson — a candidate contract, TEST don't canonize)
**Root law:** **conversation is EXECUTION context, NOT canonical memory** (G2 15-H). A patient conversation / provider session / ops incident / coding run must **never become the sole durable state** of the workflow — canonical state lives in the **governed homes, each with its own owner + gate** (durable source artifacts = S1 Source Estate · accepted reusable knowledge = S2 Knowledge Reservoir · committed domain truth = S3 Domain-Owned State · regenerable views = S5 Compiled Projection), and the run **reconstructs from them**. **No conversation→durable-memory auto-promotion** (G2 15-H/15-K: passive capture PROPOSES · passive promotion FORBIDDEN); a run may only produce *candidates* routed to a governed home's gate. Full six-category separation: **§G2C.3**.
- **`context_budget`** partitioned across: constitutional policy · task/work-package · domain evidence · conversation · **assembled Mission Context (S6 — the draw, not runtime-owned)** · runtime working/continuity memory · skill instructions · tool schemas · tool outputs · delegation returns · **reserved completion capacity**. **Seam (G2 §10):** the **Context Router assembles** the smallest-sufficient, purpose-/authority-scoped Mission Context (S6); the **runtime CONSUMES the assembled draw** and does **not** own the meaning or authority of the included content (it enforces the **intersection/meet** of its own authority ceiling and each drawn unit's admissibility/use-ceiling — not a scalar minimum; §G2C.2). The draw is logged for as-of replay (§G2C.4).
- **`context_health_state` (candidate; percentages to TEST, not lock):** `healthy <60%` · `warning 60–75%` (checkpoint + compact) · `constrained 75–85%` (no new broad work; load only necessary evidence) · `exhausted/closeout >85%` (stop broad work · preserve state · rehydrate into a fresh run).
- **Compaction MUST preserve (never an ungrounded summary that silently replaces evidence):** unresolved obligations · accepted/rejected decisions · source pointers · authority state · current owner · next action · open conflicts · exact artifacts changed.
- **Anti-evaporation tie:** this is the runtime enforcement of the estate's own recurring failure — *work leaks at pivots; the deepest cost is silent re-derivation.* Controlled checkpoint/rehydration is how a run stops being the database/ledger/log/reasoning-substrate all at once.

## §4 — Skills — governed, lane-scoped, and the hard build-vs-product line
- **Progressive disclosure** (registry): load skill name+description first · full instructions on selection · scripts/refs/assets only when needed.
- **Skill-catalog — two distinct objects (Knox-patch B):** (a) a **reusable compiled skill-catalog view** MAY be a **G2 S5 Compiled Projection** (non-authoritative, regenerable, freshness-bound); (b) the **per-run admissible skill/tool set** is a **resolved view over current S3 grants/policies** — computed from `actor × task × operator × domain × environment × risk-tier × current-authority × tool-availability` (Polaris-style; C4.1) and **recorded in run evidence**. **Inclusion/visibility in that set does NOT authorize a call** (visible ≠ authorized; re-evaluated at the point of consequence, §G2C.4-PoC). A skill that **reads** knowledge/source is additionally bound by that unit's G2 admissibility (`indexed ≠ accepted`; authority profile; currency).
- **★ HARD LINE (do NOT let a markdown skill become a healthcare capability because the harness can invoke it):**
  - **Build skill** = procedural guidance for a build agent (update a registry · generate a migration · run a security review · write a contract) — **no product authority.**
  - **Product capability** = a governed responsibility for a live product agent (prepare a refill packet · retrieve fulfillment status · assemble a clinical-review context · create a human escalation) — needs a **capability contract · authority ceiling · typed side effects · evals · versioning · proof** (`capability_envelope`, §B).

## §5 — MCP / tools — recognized but visible ≠ authorized
- **Posture (`GRD-033`):** MCP is for integration, **never governance** — wrap it behind OMNI identity/permission/audit/security/Federation. **A tool visible through MCP NEVER means the agent is authorized to call it.**
- **Connector/tool registry (candidate):** connector+tool identity/owner/version · read/write class · allowed actors+purposes · patient/operator/tenant scope · credential broker · data-classes exposed · PHI posture · rate/cost limits · timeout/retry/idempotency · health state · deprecation/kill-switch. The agent receives only tools **admissible to the current workflow lane**, authorized **per call**.

## §6 — Delegation (subagents) — a real contract, not more text poured back
Production delegation carries: parent run · delegated objective · input packet · **output schema** · authority ceiling · allowed tools · context budget · cost/time budget · deadline · termination conditions · required proof · visibility rules.

### §6.1 — Delegation posture, supervision, capture and adoption *(PROPOSED 2026-08-08 · `review_ready_pending_parent_integration`)*

> **Why this exists.** The hard laws above were authored, correct, and **never wired to the mandatory loop** — `agent_work_protocol.md` contained no delegation step at all, so nothing ever asked the questions. Decision proposed as `D0CKPT-DEC-008`.

**Four orthogonal launch facts. Do not collapse them into named "agent types."** Blind is not the opposite of supervised — a child can be supervised *and* fresh-context, or unsupervised *and* not independent. Collapsing supervision with independence produces a taxonomy that misclassifies both.

| Axis | Values | What it governs |
|---|---|---|
| `execution_posture` | `primary_collaborative` · `delegated_supervised` · `delegated_unsupervised` | how much the parent watches while the work happens |
| `capture_posture` | `structured_return_only` · `exact_submission_source_object` | whether the exact submission survives the run |
| `acceptance_topology` | `parent_review` · `named_independent_review` · `owning_authority_gate` | who may adopt the result |

**`owning_authority_gate` is deliberately abstract.** For current OMNI architecture/build work it instantiates as Nick, Knox, the Nick↔Knox↔Opus trifecta, a domain owner, or another explicitly named reviewer. **Do not bake today's trifecta into a cross-context law** — a care-facing or internal-operations agent will not be accepted by it.

**Independence is a composable CONTRACT, not a fourth enum.** The values are not mutually exclusive and an enum cannot describe a real run. Gate-1a is the proof: it was simultaneously fresh-context, blind to OMNI's answer, denied repository access, denied external research, **and** continued in the same thread between Phase A and Phase B. Declare only the fields that are materially claimed:

| Field | Values |
|---|---|
| `fresh_context` | `yes` · `no` |
| `incumbent_answer_exposure` | `withheld` · `partial` · `full` |
| `repository_access` | `none` · `bounded` · `full` |
| `external_source_access` | `forbidden` · `bounded` · `allowed` |
| `continuity_with_prior_phase` | `same_context` · `new_context` · `not_applicable` |

**This is not a form every microhelper fills** — it applies only where independence is materially claimed. It also stops a future agent asserting "fresh context" as though that proved blindness.

**Posture selection, stated as conditions rather than rules.** Stay `primary_collaborative` when the problem is tightly coupled, interactive correction materially improves the work, the judgment is highly consequential, the evaluator is weak, or the operator needs to participate in the reasoning rather than receive a result — **this remains the normal posture for central OMNI architecture.** Use `delegated_supervised` for bounded specialty or search work that benefits from another context but is not safe to release unattended. Use `delegated_unsupervised` when independence itself is the experiment, the task is genuinely bounded and auditable, or parallel breadth outweighs the loss of interaction. **Unsupervised does not mean trusted — it means the acceptance gate happens afterwards.** Use a **separate review leg** when the parent is conflicted because it authored the proposal, consequence is high, or fresh adversarial judgment is itself part of acceptance; that leg gets **its own review object and gate** and does not silently become parent truth.

**Operator visibility.** Consequential independent, adversarial or unsupervised delegation is **operator-visible before launch** — posture, expected result, evaluator, capture plan. It must not appear silently mid-work. **Routine deterministic microhelpers need no ceremony, and equally cannot originate architecture or count as independent corroboration.**

**Capture, and the pointer-referent rule.** Where the run is blind/independent/adversarial, substantively unsupervised, costly to reproduce, decision-shaping, uniquely preserving of disagreement or rejected branches, or consumed by a delayed/replacement context, `capture_posture` is `exact_submission_source_object`: the **exact assignment**, the **exact user-visible final response**, explicitly returned attachments or source ledger, plus provenance, independence conditions, cutoff, byte count and hash. **Never hidden chain-of-thought, private scratchpads, every tool event, or the whole platform transcript** — visible reasoning the author returned is part of the submission and travels with it. **This is not "save every chat."**

> **The rule the original §6 was missing:** *the commissioning parent owns the capture decision and its destination, established **before** adjudicating the result. **No pointer may reference an object nobody created.*** The child owns the bounded assignment and structured return; the reviewer or operator owns adoption.

**Source object ≠ interpretation, and neither substitutes for the other.** Two lineages run in parallel: **execution/source lineage** (what was assigned, what exactly came back, under what independence conditions, at what hash) and **interpretation/decision lineage** (what the parent accepted, narrowed, rejected or left unresolved, and which gate must consume it). A carrier preserves the second. Preservation confers **no** architecture authority — it proves what a child said, never that it was right, and external claims inside a preserved submission stay non-promotion-grade until their primary sources pass the Evidence Plane gate (`GRD-036`).
