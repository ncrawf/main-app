*(customer data, prompts, outputs, files, logs, usage metadata, training/improvement rights)*

### §2.2 Sub-finding B — Ontology / semantic ownership
*(who owns the semantic model, mappings, object definitions, workflow logic, customer-specific operational knowledge)*

### §6.1 Sub-finding A — Classic zero-trust reference model (NIST 800-207)
- **Reviewed-source reality:** ZTA = *no implicit trust by network location or asset ownership; authenticate + authorize (subject AND device) before every session.* **7 tenets:** all data/services are resources · secure all comms regardless of location · per-session access · **access by dynamic policy incl. observable state** · continuous integrity/posture monitoring · **dynamic authn+authz strictly enforced before access** · collect telemetry to improve posture. **3 components:** Policy Engine (PE, decides) + Policy Administrator (PA, executes) = Policy Decision Point; **Policy Enforcement Point (PEP)** sits inline as gatekeeper [NIST-207][ZTA-Guide].
- **OMNI analogue — strikingly isomorphic (validate + name):** OMNI's **RBAC 4-way spine** (Federation possibility · RBAC capability · owning-domain commit · CNS-Meta enforce) + **re-check at emission AND execution** ("UI hiding ≠ enforcement") ≈ **PEP inline**; RBAC 6-layer resolver + `policy_resolver` ≈ **PE/PDP**; owning-domain commit ≈ **PA**; Network Governance Plane + `trace_lineage`/`cns_decision` ≈ **continuous monitoring + telemetry**; `authority_evaluation` ("can this actor do this for this patient at this moment GIVEN current context") + **REV-184 `trust_horizon`** (authority shortened by staleness/uncertainty/irreversibility/blast-radius) ≈ **dynamic-policy-incl-observable-state, per-session**; operator-neutrality (`T0-14`) ≈ **no-implicit-trust-by-ownership**. **OMNI's authority substrate is strongly ZTA-compatible *in principle*** — it already emphasizes no-implicit-trust, repeated authorization, actor/context-aware gating, and enforcement at emission/execution.
- **Assessment:** **`validated/already-covered` (in principle) — name it** ("OMNI's authority model is strongly ZTA-compatible: RBAC-resolver ≈ PE, domain-commit ≈ PA, emission+execution gate ≈ PEP"). **But full enterprise ZTA still requires C5 security implementation** — network/device identity, mTLS, vault/secrets, SIEM/logging, deployment topology, workload identity — **not modeled** → `C5-implementation` + operating lane (§6.6). **(False-confidence guard: OMNI is ZTA-*shaped* at the authority layer, NOT a complete enterprise ZTA as-built.)**

### §6.2 Sub-finding B — Software + model supply-chain provenance (SLSA / SBOM) — the genuine absence
- **Reviewed-source reality:** **SLSA** = tamper-evident provenance of *how/where/by-whom* an artifact was built (build track L0–3) + source track (L1–4); **SBOM** = component inventory (SLSA references it, distinct purpose) [SLSA-Spec][SLSA-CMX].
