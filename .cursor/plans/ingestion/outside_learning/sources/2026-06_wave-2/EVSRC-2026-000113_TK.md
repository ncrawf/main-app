Core takeaway

The keeper is:

Agent traces are becoming their own data infrastructure problem.

That matters for OMNI because once agents are doing real work, their traces will not be cute little logs.

They will include:

inputs,
context packets,
model calls,
tool calls,
subagent steps,
file changes,
code execution,
human approvals,
messages drafted,
actions proposed,
domain commits,
errors,
forks,
replays,
costs,
latencies,
screenshots,
voice/image/media,
and evidence links.

Traditional app logs may not be enough.

The big OMNI translation

Agent traces are behavioral records.

This source reinforces the ADLC keynote point: a trace is not merely debugging output. It is the behavioral record of what the agent actually did.

OMNI translation:

Agent traces may become evidence for:

why an action was proposed,
what context was used,
what tool was called,
what the agent omitted,
what human approved,
what failed,
what changed,
and what should be improved.

Keeper:

A trace is the behavioral record of an agent under authority.

Observability becomes data architecture.

large payloads,

long sessions,
multimodal traces,
high volume,
trace search,

fast random access,
data residency,
cost control.

OMNI should not assume generic logging solves agent oversight.

Keeper:

Agent observability is a data platform, not a log viewer.

OMNI should be careful here.

Not every trace is a D7 artifact.
Not every trace should be permanent evidence.
Not every trace should be visible to every user.
