This one is core spine material. Not because every Sequoia market claim should become OMNI doctrine, but because this video gives the broadest frame for the entire batch:

AI is attacking both software and services, the application layer is where domain companies win, agents evolve into an economy, and everyone has to adopt a stochastic-management mindset.

For OMNI, this is not a side source. This is a thesis-orientation source.

Core takeaway

The keynote argues that AI is not only a software market shift. It is a software + services + labor/work shift. AI products can begin as tools, become copilots, become autopilots, and eventually sell outcomes/work into labor budgets instead of only selling software into software budgets.

That is directly OMNI-relevant because OMNI has never really been “just software.” OMNI is trying to absorb care coordination, documentation, scheduling, messaging, follow-up, operations, business logic, workforce support, evidence handling, and eventually agentic work.

The sharper framing:

OMNI’s market is not EHR/SaaS replacement. OMNI’s market is governed care/business work.

OMNI translation
1. This validates OMNI as application-layer, vertical, customer-back AI.

Sequoia’s message is: foundation models will push into the application layer, so startups need to go customer-back, vertical-specific, function-specific, and solve complex problems where human-in-the-loop and domain nuance matter.

That is exactly OMNI’s path.

OMNI should not compete on “we have a smarter model.” It should compete on:

care workflow truth,
clinical/business authority,
patient/provider/operator context,
domain-specific seams,
governed action,
longitudinal context,
trust,
deployment closeness,
workflow outcomes.

Keeper line:

OMNI wins by being of the care/workflow domain, not by being a wrapper over intelligence.

2. “Application layer value” is not enough; OMNI needs defensible application physics.

The keynote says value accrues at the application layer, but also warns that foundation models are coming into that layer through reasoning, tool use, and inter-agent communication.

So “application layer” alone is not a moat.

For OMNI, the moat has to be:

domain truth ownership,
workflow-specific agent harnesses,
patient/care/business data flywheels,
authority-labeled context,
clinical/adoption gates,
trust and deployment depth,
evals tied to care/business outcomes,
operator/provider/patient feedback loops.

This reinforces the earlier Serval/Pace/Cursor lessons: the product is not just an app; it is the domain-specific boundary + workflow + eval + data flywheel system.

3. Data flywheel must move a business/care metric.

This is one of the best practical warnings in the video.

Sequoia says a data flywheel only matters if it moves a business metric. Otherwise it is not a moat.

OMNI has tons of possible “data flywheels”:

patient messages,
intake responses,
labs,
outcomes,
provider decisions,
workflow traces,
staff corrections,
scheduling behavior,
commerce/entitlement behavior,
evidence-source interpretations,
care pathway completions,
patient support network inputs.

But not all of that matters automatically.

OMNI should ask:

Which metric does this learning loop improve?

Examples:

fewer missed follow-ups,
faster provider review,
fewer unsafe message replies,
better refill readiness,
fewer scheduling/payment/document mismatches,
higher patient adherence,
lower staff labor per care episode,
better clinical escalation precision,
fewer unresolved tasks,
higher patient trust.

Doctrine line:

No data flywheel is real until it improves a named care, operational, safety, trust, or financial metric.

4. “Vibe revenue” has an OMNI equivalent: vibe automation.

The keynote warns that AI companies can mistake tire-kicking revenue for durable behavior change.

OMNI’s equivalent danger is vibe automation:

demo looks amazing,
team says “wow,”
agent drafts something impressive,
workflow still isn’t adopted,
provider still does it manually,
staff still works around it,
patient trust does not improve,
safety/eval layer is weak.

So OMNI needs durable behavior-change metrics, not demo applause.

Keeper line:

Do not confuse impressive AI output with adopted workflow change.

5. Trust is more important than product at this stage.

This is extremely relevant to care.

The keynote says customers need to trust that the product will get better. In OMNI, trust is even more central because the product touches safety, identity, consent, money, documentation, provider authority, and patient relationships.

OMNI should not over-index on magical automation. It should be the “rock” from the Pace video:

dependable,
auditable,
conservative at commit boundaries,
transparent about uncertainty,
fast to improve,
clear about what AI did and did not do.

Doctrine line:

In care, trust is not a brand layer. Trust is runtime architecture.

6. Agent economy maps directly to §C.

The keynote’s “agent economy” section is very important. It says agents will not only communicate information; they will transfer resources, transact, track reliability, understand trust, and participate in an economy.

That is basically §C.

OMNI needs to prepare for:

patient agents,
provider agents,
payer/pharmacy/lab/vendor agents,
internal OMNI agents,
external foundation-model agents,
marketplace-like capability exchange,
agent authentication,
payment/entitlement,
trust/reliability records,
agent permissions and revocation.

Keeper line:

OMNI should not merely talk to agents; it should govern what agents can request, exchange, transact, and commit.

7. The three agent-economy prerequisites are exactly OMNI’s hard problems.

The keynote names three technical prerequisites:

persistent identity,
seamless communication protocols,
security/trust.

That is a huge confirmation for OMNI.

OMNI’s §C cannot just be “APIs for agents.” It needs:

persistent identity for humans, organizations, agents, devices, robots, caregivers, vendors;

security models for non-human actors;
auditable capability invocation;
consent and purpose-of-use.

Doctrine line:

Agent interoperability without persistent identity and security is not capability exchange; it is attack surface.

This is maybe the most important conceptual section.

Sequoia says we are moving from deterministic computing to stochastic computing: more leverage, less certainty. That is exactly why OMNI cannot use old SaaS mental models alone.

OMNI must manage stochastic intelligence through deterministic boundaries.

authority,

The keynote says much of the economy will move from IC work into managing agents: knowing what agents can/can’t do, blocking processes, giving feedback, and handling leverage with uncertainty.

OMNI users are not just “clicking software.” They will increasingly manage agents:

Keeper line:

The OMNI user is not only a user; they are an agent manager.

OMNI is not one giant brain. OMNI is a governed network of actors, agents, reservoirs, workflows, and domains with explicit authority boundaries.
