## 2. ChatGPT distillation

<Ingested into the active AI substrate / OMNI build thread. Memory is full, so this is thread-context only until we convert the full AI trove into an OMNI artifact.

This one is foundational for the memory architecture layer.

Core taxonomy captured:

1. Working memory
The context window: current conversation, instructions, loaded files/data. Fast, immediate, volatile, limited, and degraded if overstuffed.

2. Semantic memory
What is generally true: facts, rules, policies, docs, architecture, coding conventions, knowledge graphs, vector DBs, or markdown files like CLAUDE.md / AGENTS.md.

3. Procedural memory
How to do things: skills, skill.md, repeatable workflows, step-by-step procedures, scripts, templates, and progressive disclosure.

4. Episodic memory
What happened before: compressed experience, prior interactions, decisions, mistakes, lessons learned, prior debugging history. Not transcript hoarding — distilled memory.

OMNI mapping:

Working memory = active context packet / case packet / current orchestration state.
Semantic memory = doctrine, domain truth, policies, clinical knowledge, operator configuration, project architecture.
Procedural memory = skills, Build OS workflows, clinical/ops playbooks, agent work packages.
Episodic memory = traces, prior runs, lessons learned, patient/operator longitudinal experience, “what happened last time.”

Big OMNI phrase:

A chatbot has working memory. An agent needs working, semantic, procedural, and episodic memory — each governed differently.
