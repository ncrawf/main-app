This one reinforces the optimization-method router bucket:

Prompt engineering = better use of existing model capability.
RAG = adds external/up-to-date/domain facts at runtime.
Fine-tuning = changes model weights for specialized patterns/expertise.

The OMNI-relevant takeaway is not “pick one.” It is:

OMNI needs an AI optimization strategy router.

For any AI workflow, OMNI should decide which optimization method is appropriate:

Prompt/template first when the model already has the capability and needs better instructions, format, examples, or role framing.
RAG/context engineering when the workflow requires current/private/domain-specific facts, patient/operator data, evidence, documents, policies, or longitudinal context.
Fine-tuning only later when there is a stable, repeated, high-volume task with a strong gold dataset and when prompt/RAG/tools are not enough.
Combination mode for serious workflows: prompt template + retrieved context + tool capability + evals, with fine-tuning optional only after evidence.

This also strengthens a governance rule:

Do not use fine-tuning to encode volatile facts, policies, clinical knowledge, operator-specific data, or workflow rules. Those belong in retrieval, Settings/config, rules/templates, skills, capability servers, and domain truth.

Prompting shapes behavior. RAG supplies facts. Fine-tuning changes the model. Skills teach procedure. MCP exposes tools. Evals decide whether any of it works.
