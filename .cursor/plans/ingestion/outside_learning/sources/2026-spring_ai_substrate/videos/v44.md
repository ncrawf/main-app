## 2. ChatGPT distillation

<Captured in-thread. This is a critical one for OMNI — more important than it looks.

The headline is: agentic AI failures are usually system-design failures, not just model hallucinations. The transcript explicitly pushes against the lazy explanation of “the model hallucinated” and instead names predictable engineering failures: infinite loops, hallucinated planning, and unsafe tool use.

For OMNI, this belongs in the Agentic Runtime / CNS / Build OS Runtime Proof spine.

The three failure modes OMNI must design against
1. Infinite loops

Agent keeps cycling:

search → evaluate → replan → search → evaluate → replan

This happens when there is no clear stop condition, no action-difference tracking, and no progress tracking.

OMNI translation:

Every agentic workflow needs:

max step count
max retries
max runtime
max cost
progress score
repeated-action detection
“answer not found” / “cannot complete” exit path
escalation path to human, CNS, or owning domain

This is especially relevant for OMNI search, clinical review, longitudinal monitoring, document retrieval, prior-auth, scheduling resolution, patient outreach, and build-agent repo work.

Key primitive candidates:

termination_condition
max_step_budget
progress_delta
retry_fingerprint
action_similarity_score
no_progress_exit
agent_run_state

2. Hallucinated planning

Agent creates a plan that sounds plausible but assumes tools, permissions, data, or capabilities it does not actually have.

Example from the transcript: planning to book a flight and send email confirmation despite not having travel API access or an email tool.

OMNI translation:

This is huge. OMNI cannot let AI create beautiful impossible plans.

Every AI-generated plan needs validation before execution:

Does this tool exist?
Is the tool available in this tenant/operator/context?
Does the agent have authority to use it?
Are required inputs present?
Are constraints satisfied?
Is this a read, write, delete, clinical, financial, or communication action?
Does this require human review?

Key primitive candidates:

plan_proposal
plan_validation_result
capability_manifest
tool_capability_schema
missing_requirement
constraint_check
execution_allowed
execution_denied_reason

This reinforces the doctrine: AI proposes; deterministic runtime validates; authorized humans/domains execute or commit.

3. Unsafe tool use

Agent performs an action that is technically valid but risky, destructive, unintended, or overprivileged.

This is where OMNI could get truly dangerous if underbuilt: deleting records, sending unreviewed messages, changing medication instructions, applying discounts/refunds, altering appointments, releasing clinical info, touching PHI, or writing to the codebase.

OMNI translation:

Tools must be permission-tiered:

read-only
draft/propose
write with validation
write with human approval
destructive / irreversible
clinical-risk
financial-risk
external-communication
codebase-modifying

The phrase I’d preserve:

Principle of least agency.

Not just least privilege. Least agency. The agent gets the minimum autonomy needed for the task.

Key primitive candidates:

tool_risk_tier
agent_permission_scope
read_write_delete_boundary
approval_required
human_authorization_event
destructive_action_guard
rollback_available
audit_trace

OMNI doctrine insertion candidate

This should probably become a binding AI-runtime rule:

Agentic failures are predictable runtime failures, not mysterious model events. OMNI agents must operate inside explicit termination conditions, capability manifests, plan-validation gates, progress tracking, action traces, permission tiers, and approval workflows. No agent may infer its own tool authority, assume unavailable capabilities, continue indefinitely without progress, or execute high-risk actions without an owning-domain authorization path.

Where it belongs

Thesis: AI substrate / agentic runtime section
System Map: maybe not as a domain, but as cross-cutting AI Runtime / CNS infrastructure
Contracts: CNS, Messaging, Intake, D7, Observation, Clinical Memory, D6, Federation, RBAC, AI/Model Lineage
Build OS: Runtime Proof Layer + Command/Tool Layer
Security/Governance: agent permissions, approval gates, audit, rollback, evals

My read

This is one of the “don’t miss for a 1BN company” lessons.

The immature version of OMNI is: “we’ll add AI agents.”

The mature version is: OMNI has an agent operating system with bounded autonomy, typed tools, validated plans, monitored progress, risk-tiered execution, and deterministic authority gates.

That distinction is the difference between impressive demo and durable company.>
