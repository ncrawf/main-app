## 2. ChatGPT distillation

<Ingested — and this one is very high priority for OMNI. This is not just “cool agent architecture.” This is directly about how OMNI avoids becoming one overloaded magical AI brain.

Core concept: single-agent architectures fail under scale because the agent gets buried in its own context, tools, and task chain. The transcript names the main failure modes clearly: context dilution, tool saturation, “lost in the middle,” bad task decomposition, brittle handoffs, recursive loops, and telephone-game distortion.

The OMNI translation:

Do not build one CNS super-agent.
Build a governed hierarchy of scoped agents.

At minimum, OMNI needs:

1. High-level orchestration agents
These own goal framing, decomposition, priority, routing, conflict detection, and state awareness. In OMNI language, this aligns with CNS / Patient-CNS / Operator-CNS / Governance-CNS.

2. Mid-level domain agents
These operate inside bounded domains: Intake, Messaging, Clinical Memory, D7, Observation, D3, D5, D6, Federation, RBAC, Settings, Build OS, etc. They translate orchestration intent into domain-specific work.

3. Low-level specialist agents/tools
These do narrow execution: extract a lab value, classify a message, validate consent status, draft a patient reply, run a schema check, search a file, generate a migration, compare two contract sections.

The big design principle:

Every agent receives a contextual packet, not the whole universe.

That is a major OMNI primitive. We already had “context packet” in CNS, but this makes it sharper: context packets are not just audit artifacts; they are agent-work payloads. They must be scoped, pruned, authority-labeled, source-labeled, and task-specific.

This also gives us a cleaner Build OS doctrine:

Build OS should be hierarchical too.
Not “Opus, please fix everything.” More like:

Architect / Planner agent: decomposes work, selects lanes, defines output contract.
Domain contract agent: updates one domain or seam.
Implementation agent: edits code/schema/types.
Reviewer agent: checks invariants, drift, tests, contradictions.
Runtime proof agent: verifies that doctrine became enforceable code.

But the transcript’s warning is equally important: hierarchy does not magically solve quality. Bad decomposition at the top poisons everything below it. So OMNI needs:

decomposition traces
task-packet contracts
handoff validation
supervisor review
retry / escalation logic
narrow tool permissions
“top agent plan is provisional, not truth”
evals for decomposition quality, not just final output

This should become a core AI Substrate Thesis insert and a Build OS insert.

Key primitives: agent_hierarchy, agent_role, context_packet, task_packet, handoff_contract, supervisor_validation, tool_scope, decomposition_trace
Do-not-miss lesson: OMNI cannot scale as one AI brain. It needs governed hierarchical agents with scoped context, scoped tools, and explicit validation.>
