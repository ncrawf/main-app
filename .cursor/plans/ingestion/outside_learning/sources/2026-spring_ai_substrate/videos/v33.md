## 2. ChatGPT distillation

This adds a missing piece to OMNI: reasoning budget as runtime policy.

The core idea: train-time compute is the fixed cost baked into model weights; test-time compute is extra inference-time work spent per query. That can include reasoning tokens, branching/search, verifier scoring, and self-consistency across multiple reasoning paths. It can improve hard reasoning, but increases latency/cost and can degrade simple answers through overthinking.

OMNI translation

OMNI should not treat “reasoning model” as a yes/no model choice.

It needs an adaptive AI picker/router:

simple task → fast model / single-pass inference
ambiguous or high-risk task → reasoning model
clinical/safety-critical task → reasoning + retrieval + verifier + policy gate + human review when needed
cheap repetitive task → small specialist model or deterministic workflow
build/code task → planning/reasoning budget based on blast radius

This belongs in the AI Substrate, not just the AI domain contract.

Why this matters for 1BN-company OMNI

At scale, “let the model think harder” becomes a business, safety, and latency decision. OMNI needs to know when to spend compute and when not to.

Potential primitives:

reasoning_budget
test_time_compute_policy
task_complexity_score
risk_tier
latency_budget
cost_budget
overthinking_guard
reasoning_required_reason
reasoning_trace
verifier_required
self_consistency_required
human_review_threshold
Build OS implication

Same applies to Opus/Cursor building OMNI.

Do not send every coding task into unlimited “deep think.” Route by risk:

doc cleanup: low reasoning budget
domain contract changes: medium/high
migrations/schema changes: high + verifier
auth/clinical/PHI/security changes: high + multi-pass review + tests + explicit proof
broad architecture refactors: planning mode before code mode

This is another argument for an Agentic Control Plane: not just “which tool can the agent use,” but how much reasoning is authorized, under what risk tier, with what proof obligation.>
