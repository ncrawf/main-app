This one belongs in the multi-agent team design / role architecture / Build OS agent staffing bucket.

Core concept:

Complex agentic work should be designed like a team, not like one giant prompt.

The transcript lays out a clean set of agent roles: doer, planner, tool operator, learner, feedback/critic, supervisor, and presenter. It also emphasizes that each role can be made better through prompting, model selection, model tuning, and scoped context.

OMNI-relevant takeaways

1. Agent roles need contracts.
OMNI should not just say “AI agent.” It should define role contracts: what the role may do, what inputs it receives, what outputs it produces, what tools it can call, what context it can see, and who verifies it.

2. CNS maps naturally to supervisor/orchestrator.
The supervisor role checks progress, detects stuck workflows, coordinates handoffs, and routes failures. That is CNS territory — but CNS should govern the loop, not hallucinate final truth.

3. Learner = retrieval/context agent.
This maps directly to OMNI’s context router, RAG/GraphRAG, source search, evidence gathering, and external knowledge access. The learner does not commit truth; it gathers and filters candidate context.

4. Tool operator = capability caller.
This is the MCP/capability-server layer. Tool operators should create structured tool calls, pass validated arguments, receive structured results, and preserve trace/audit.

5. Critic/verifier is mandatory for high-stakes care.
The feedback role checks hallucinations, policy adherence, extraction accuracy, generated code/tests, and output quality. For OMNI, this becomes clinical verifier, policy verifier, source verifier, safety verifier, or adversarial reviewer depending on the workflow.

6. Presenter is a separate role.
The agent that synthesizes internal work into a patient/provider/operator-facing response should not be assumed to be the same thing as the planner, retriever, or committer. This matters for messaging, D7 summaries, provider-facing notes, and patient explanations.

Build OS implication

This is a direct blueprint for AI on OMNI:

Supervisor = owns work package status and final routing.
Planner = decomposes task into steps.
Learner = pulls relevant architecture/domain context.
Tool operator = runs tests, search, migrations, file edits, MCP/capability calls.
Doer = writes code/docs/contracts.
Critic/reviewer = validates against invariants, tests, doctrine, and acceptance criteria.
Presenter = writes the final handoff/proof.

Phrase to preserve:

OMNI should staff agentic workflows with bounded roles, not generic agents. Each role gets the minimum context, tools, model, and authority needed for its job.>
