Really good explanation of why agents are becoming an infrastructure problem, not just an application problem.

This matches what I’ve been seeing while building agentic systems in production.

The deeper challenge is that agentic systems introduce entirely new failure modes most current infrastructure was never designed for:

* Non-deterministic runtime → same task can take seconds or hours
* No execution envelope → no predictable bounds on runtime or tool depth
* No agent identity standard → OAuth was built for humans, not autonomous agents
* Cost explosion across agent trees → recursive agents can multiply token usage unpredictably
* Missing durable HITL → pausing/resuming agents cleanly is still unsolved
* No cross-framework interoperability → agents and memory systems remain siloed
* No standard agent-to-agent trust model → delegation and scoped permissions are fragmented
* Reflection loops without convergence → agents can keep “thinking” indefinitely
* Limited failure isolation → one runaway agent can impact an entire fleet
* Missing rollback primitives → agents can take irreversible actions without recovery guarantees
* Weak observability standards → traces, reasoning paths, and tool calls are not portable
* No unified policy layer → governance is fragmented across frameworks

Feels like the industry is entering the same phase distributed systems and cloud infrastructure went through before standardisation emerged.

Agent OS primitives from the transcript

1. Scheduler / Orchestrator
Decides what runs first, what waits, what has priority, and how agents share limited model/tool resources.

OMNI mapping: CNS orchestration, task priority, care urgency, live patient message vs background summarization, provider queue ordering.

2. Memory Manager
Manages short-term, long-term, and episodic memory.

OMNI mapping: working context packets, patient/operator longitudinal memory, trace history, prior failed/successful paths, case cache.

3. Tool Manager
Controls what tools exist, who can use them, and sandboxes execution.

OMNI mapping: capability registry, MCP/capability servers, tool permissions, vendor adapters, no raw database/API access for agents.

4. Identity Manager
Answers: who is this agent, on whose behalf is it acting, and what is it allowed to do?

OMNI mapping: agent identity, user delegation, operator boundary, Federation, RBAC, scoped tokens, audit lineage.

5. Observability
Logs every decision, tool call, response, and action so you can rewind the tape.

OMNI mapping: source_event → candidate → resolver → capability_call → commit/projection, trace replay, evals, audit.

6. Guardrails / Governance
Input checks, output checks, human-in-the-loop, data boundaries, and “too important to automate” rules.

OMNI mapping: autonomy levels, clinical authority gates, consent gates, policy gates, human review, escalation.
