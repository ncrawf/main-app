## 2. ChatGPT distillation

<Ingested.

This one goes into the context-mode router / RAG-CAG hybrid bucket.

Core distinction:

RAG retrieves the relevant slice from a large/dynamic knowledge base.
CAG preloads a bounded/static knowledge set into model context or cache for faster repeated reasoning.

The OMNI-relevant lesson is the hybrid clinical example at the end: for clinical decision support, the answer is not RAG or CAG — it is both. Use RAG to retrieve the relevant patient history, treatment guides, research, policy, or drug interactions, then load that bounded retrieved set into a long-context/cached working memory for the specific case.

This is a direct OMNI primitive:

Case Context Cache or Working Context Packet

Possible rule:

For large, dynamic, longitudinal corpora, OMNI retrieves. For bounded case work, OMNI assembles and caches a scoped working packet. For clinical/high-risk workflows, the packet must be source-labeled, freshness-aware, permission-gated, replayable, and invalidated when source truth changes.

Important design implications:

RAG for scale and freshness
Use for giant data sets: patient history, operator policies, clinical guidance, documents, prior messages, labs, longitudinal observations.
CAG / long-context cache for bounded case reasoning
Use once OMNI has assembled a relevant case packet and needs repeated follow-up questions, case review, or multi-step reasoning without re-retrieving every time.
Hybrid for care workflows
This is probably the default for serious OMNI clinical/provider workflows:
retrieval → context assembly → context compression → case cache → reasoning → trace/eval.
Cache invalidation becomes safety-critical
In OMNI, cached context must expire or invalidate when patient data, consent, visibility, clinical adoption, medication list, lab values, or policy changes.
RAG accuracy depends on retriever quality
So retrieval evals are required: did we retrieve the right patient record, the right doc, the right policy, the right observation, the right timestamp?

The phrase I’d keep:

OMNI should retrieve broadly, assemble narrowly, cache temporarily, reason traceably, and invalidate aggressively.>
