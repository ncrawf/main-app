## 2. ChatGPT distillation

<Ingested into the active thread only. Memory is full, so this needs to go into the eventual OMNI AI-substrate artifact rather than relying on saved memory.

This one belongs in the CAG / long-context / prompt-cache / context economics bucket.

Core distinction:

Long context means putting the bounded document set directly into the prompt every time. It is simple and avoids retrieval-miss risk, but cost and latency recur on every query, and the transcript flags the “lost in the middle” problem where models attend better to the beginning/end than buried middle content.

CAG — Cache-Augmented Generation means the model reads a stable knowledge packet once, precomputes/persists the KV cache, then reuses that cached representation for later questions. It is best when the knowledge base is stable and queried repeatedly; if source data changes frequently, cache recomputation can erase the benefit.

OMNI implication:

Context mode is not just accuracy architecture. It is cost, latency, freshness, and safety architecture.

Likely OMNI modes:

long_context_oneoff — one-time analysis of a bounded packet/document.
cached_context_stable — stable policies, playbooks, guidelines, operator docs, product/service docs.
retrieval_dynamic — patient state, messages, labs, observations, changing policies, live workflows.
hybrid_retrieve_assemble_cache — retrieve dynamic sources, assemble a case packet, temporarily cache for active work.

Important safety rule:

Cached context is not truth. It is a performance artifact over truth.

For OMNI, any case/policy/context cache needs source lineage, version hash, consent/visibility snapshot, TTL, invalidation triggers, and a replayable context assembly trace.>
