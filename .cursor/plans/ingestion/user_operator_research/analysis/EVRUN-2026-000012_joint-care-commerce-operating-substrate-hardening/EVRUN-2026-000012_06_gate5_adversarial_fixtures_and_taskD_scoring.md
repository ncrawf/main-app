## §6.0 — Method, scoring grammar, and honesty posture

**What Gate 5 is (A-correction — honest reclassification):** a **self-authored design-conformance and pressure suite** — construct hard scenarios (normal + failure), run each against the accepted architecture + patched product model, and score whether the laws have a coherent target-state answer. **It is NOT independent falsification:** the same Opus instance authored the fixtures, the expected in-bounds behavior, AND the scoring, so the result is **correlated by construction**. Every "HOLDS" means *the architecture has a coherent, in-bounds **target-state** response* — **not** that an independent adversary failed to break it, and **not** that running code proves it. Independent reproduction, copyability, and differentiation are **Task-D burdens**; runtime/pilot proof is owed downstream. The suite's value is **broad semantic coverage + a pre-registered fixture bank + a maturity-gap map + a product-risk map**, not a moat claim.

**Task-D capability profile (6 axes)** — scored per fixture:
- **Rep** = Represent (can the model hold the distinct states/relations without collapsing them?)
- **Enf** = Enforce (does a gate/law actually block the bad transition?)
- **Aut** = Authorize (is the right actor/authority required to commit?)
- **E&R** = Execute-and-recover (does execution + failure/retry/compensation/reopening work?)
- **P/R** = Prove/replay (is there attributed, replayable evidence?)
- **Learn** = Learn-without-rewriting-history (can it adapt without falsifying the past?)

**Verdict legend per axis:** `H` HOLDS (in-bounds answer exists) · `B` BENDS (supported but thin / needs config / unproven / partial impl) · `X` BREAKS (genuine gap — routes to Gate 6/7) · `–` N/A.

**Cross-cutting columns:** **Impl** (from Gate-2 census: `BUILT`/`PARTIAL`/`UNBUILT`) · **CfgBurden** (operator config burden Low/Med/High) · **Acct** (accountability traceability Y/partial/N) · **CopyHyp** (*unvalidated copyability HYPOTHESIS* — how hard an incumbent composition MIGHT find it to replicate; Low/Med/High). **`CopyHyp` is a pre-registered Task-D input, NOT a Gate-5 moat finding** (A-correction) — it is a candidate differentiation cluster for Task-D attack, nothing more.

**Honesty guard:** a fixture that only "HOLDS" on paper is still `design-level`. The **decisive Gate-5 output is R1–R6** (§6.3), because those are where the patched model's Day-1 product claim lives or dies.
