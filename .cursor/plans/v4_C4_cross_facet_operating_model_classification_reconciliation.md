## §1 — Classification AXES (NOT a nested hierarchy — a lane spans several at once)

**★ CORRECTION (fresh-Knox 2026-07-27):** these are **largely ORTHOGONAL classification axes, NOT nine nested levels.** A single lane (e.g. pharmacy) can *simultaneously* involve an external-counterparty **facet** + an externally-owned execution **lifecycle** + one or more OMNI conformance **profiles** + several **domains** (OFC/D6/Federation/Settings) + **controllers** (CNS/OFC) + transport **rails** + UI **projections** + Reactor-applicable **invariants**. Forcing a lane into ONE genus ("Pharmacy = profile family") flattens exactly what the rubric must preserve. **The output of classification is a TUPLE across these axes, not a single bucket.** The list below enumerates the *kinds* (axes), it does NOT rank them and must NOT be frozen as a ladder:

1. **Thesis operating pattern** — `Sense + Act with authority gates` (the constitution; not itself a loop instance).
2. **Captured coupled loops** — concrete Sense/Act specializations with their own locus, authoritative resolution, execution, proof, and reopening behavior. Current captured set: **Care · Platform · Accountability/GRR** (each nonbinding-captured, coupled — not independent).
3. **Native lifecycle families** — coherent end-to-end lifecycles beneath/across loops: Care-Resolution · Sourcing-Selection · Fulfillment/OFC · Financial-Settlement/D6 · Operator-Configuration · Platform-Change · Accountability-Response. **A real episode composes several without becoming one mega-loop or one universal record.**
4. **Cross-cutting concerns / facets** — threads that traverse many loops/lifecycles without being a loop themselves (e.g., Demand/Engagement threading Sense-ingress → governed exchange → Platform release → CNS runtime → commerce → identity → rights → accountability).
5. **Conformance / profile families** — a *way distributed owners compose* for a class of counterparty/case, NOT a new owner (e.g., Pharmacy as a counterparty execution/conformance-profile family spanning existing owners).
6. **Domains** — truth-owning bounded contexts (OFC, Federation, D6, Settings, CNS, D7, RBAC, Clinical Memory, Identity, etc.).
7. **Seams / controllers** — where domains meet + who advances state (a projection is NOT a controller; CNS is NOT a universal executive).
8. **Projections / surfaces / rails** — read-models, UI, transport. Own no canonical truth.
9. **Reactor** — presently a **candidate constitutional test over consequential transitions** — NOT a domain, object, service, executive, or additional loop. It may *test* a lifecycle without *owning or defining* it. Non-ontological role; unpromoted/frozen.

## §2 — Provisional cross-facet classification rubric v0 (review QUESTIONS only — NOT a frozen ontology)

**★ CORRECTION (fresh-Knox 2026-07-27):** approve/apply these as **stable review QUESTIONS** (a consistent instrument for arc-closeouts) — do **NOT** "freeze a shared ruler / final taxonomy." Insurance and Reservoir are meant to *test and possibly bend* this; permanently freezing it before those falsifiers run would overfit it to Care/Demand/Pharmacy. It is used as a **review instrument, not accepted cross-facet doctrine.** The result of applying it is a **classification TUPLE (§1), not a single genus.**

- **A · Locus of effect** — what is principally changing? (patient/care relationship · platform capability estate · an accountable concern/remedy · an external counterparty's execution state · a commercial relationship · a benefit/coverage position · a public/private relationship boundary).
- **B · Authoritative truth & commit** — who can commit the decisive state? (clinician · patient · platform release authority · pharmacy · payer · operator · financial rail · regulator · other independently-authorized party).
- **C · Native lifecycle** — does it have a coherent end-to-end lifecycle of its own, or is it a composition of existing lifecycles? **Compare EQUAL SPANS** — never one process end-to-end vs another truncated at "publish/send."
- **D · Orchestrator / controller** — who advances it? (Care/CNS · Platform E&V/Release/Runtime · Accountability controller · OFC · external counterparty · composed policy/controller). *A projection is not a controller.*
- **E · Custody, closure & reopening** — what can fail, terminate, transfer, remain unresolved, or reopen another domain? (this is where sourcing ≠ fulfillment, pharmacy-acceptance ≠ transport-ACK, payer-denial ≠ clinical-rejection).
- **F · Composition sufficiency** — can existing domains/lifecycles/seams/controllers preserve all necessary truth, authority, obligation, and proof? **If yes → not a new loop.** If no → the failure must name EXACTLY what is missing: owner · lifecycle · seam · policy · visibility · delegation · commitment · custody · dispute/remedy · or a truly distinct recursive loop.
- **G · Reactor relationship** — do the Reactor invariants apply? **This alone does NOT classify genus** (invariant-counting rejected). Reactor may test the lifecycle without owning it.
- **H · Classification tuple (the OUTPUT)** — what tuple across the §1 axes results? A lane may be **several kinds at once** (facet + external lifecycle + conformance profiles + domains + controllers + rails + projections + applicable invariants). Never collapse to one bucket; name each axis the lane occupies and why.
