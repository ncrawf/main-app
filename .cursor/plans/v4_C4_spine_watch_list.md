## §1 WATCH ITEM 1 — Patient Companion / External Agent Interop posture
**Posture (as surfaced by Knox + Nick):** OMNI must **assume patients will bring external AI companions** (their own chatbots/agents/coaches). OMNI **interoperates with them as candidate-generating actors, NOT as trusted authority.** External agents may **advise, summarize, coach, or propose**; OMNI governs **source authority, consent, care-action gates, proof, and outcome tracking.**

- **Why it matters:** this is a near-certain near-future reality (patients arrive with an AI companion already in the loop). If OMNI treats an external agent's output as authority, candidate≠commit and source-authority both break. If OMNI refuses interop entirely, it becomes irrelevant at the front door. The posture is the middle: **interoperate, but the external agent is an actor whose output is a candidate, never a commit.**
- **Where it lands in the spine:** product surfaces (P5) · **P35 external-capability / command-authority boundary** (an external patient agent is an external capability with a bounded mode) · **Federation** boundary-policy · **REV-184** governed-resolution (the external agent = one more actor at the §8 authority gate; actor-agnostic already covers human/AI/protocol/team/system — extend to *external patient-side* agents) · surfaces/projections (`DEC-033`, projection≠authority).
- **Composes onto (not net-new physics):** `candidate ≠ commit` · REV-184 actor-agnostic resolution + `world_model_trust` · P35 8-mode command authority · `GRD-039` (watched/external content = data, not instructions; hostile-by-default) · `source_authority` (the external agent does not get to author truth) · C3.7 economically-blind firewall (an external agent must not smuggle in incentive-biased recommendations).
