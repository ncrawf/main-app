## 0. How we got here (the realization)

Naming an evidence-ingestion folder forced a zoom-out. The chain: *which lane? → lanes are source families → the Evidence Plane is one body of knowledge → there are MANY bodies of knowledge OMNI draws on → they form a family → the thing that draws on them is the CNS → **the CNS has no framework.***

**The load-bearing insight:** OMNI has rich definition for the **substrate** (P1 domains/truth), **surfaces** (P5), and **projections** (P4). The **CNS** — the orchestrating "brain" that assembles context, draws on knowledge, routes, drafts, and escalates — has been hand-waved ("the CNS does it"). It is **as central as the substrate** and currently lacks a comparable framework/taxonomy. This doc reserves that gap.

> This is NOT a request to define the CNS tonight. It is a request to *not lose* what we found while naming a folder.

## 1. The parent category (PROVISIONAL: "Knowledge Reservoirs")

A **family/classification** (NOT a new plane, NOT a domain, NOT "substrate" — that word is reserved for OMNI-the-substrate, `GRD-035` noun-discipline) of **governed bodies of retrievable knowledge/context that the CNS / agents / surfaces / build may draw on when assembling context, reasoning, routing, drafting, or deciding.**

- **It is cross-plane:** some members are P1 domain truth, some are the Evidence workbench, some are Build OS, some are future security ops, some are future clinical literature/RAG. The unifying rule is NOT "same plane."
- **Industry equivalents** (no single canonical noun): the *knowledge / grounding layer* (IBM "knowledge/data fabric"; Google "grounding" + knowledge graph; Anthropic / AI-eng "context engineering," "retrieval/RAG," agent "memory"). Members = *knowledge bases / corpora / context sources / grounding sources.*
- **Brain analogy** (on-brand, the way to explain it): the **CNS = orchestrating brain/executive**; the reservoirs = the **knowledge & memory regions it consults**; the **domains = where truth is committed.** Members are "regions the brain queries," not a plane and not parts the CNS owns.

## 2. The reservoir contract (PROVISIONAL — what makes something a member)

Every member carries:

| field | meaning |
|---|---|
| `authority_class` | how authoritative its knowledge is — **members are NOT equal** (non-binding outside reference → clinically-governed → patient-specific truth → …). This is the loudest field. |
| `owner` | who governs it |
| `review_gate` | how knowledge enters + how it is allowed to be used (promotion/use gate) |
| `retrieval_use_boundary` | how CNS/agents query it + what it may/may not inform (esp. care-authority boundary) |

**Binding law (the anti-"brain-owns-everything" rule):**

> **CNS orchestrates · Reservoirs supply governed context · Owning domains commit truth.**

**Operating principles (shared across the whole family):** every reservoir obeys the Evidence Plane's substrate-grade operating principles (`ingestion/00_evidence_router.md` → "Operating principles" + `D0THES-GRD-042`): immutable source · versioned + attributed interpretations · reinterpretation expected · gated promotion · scout-not-legislator · index-as-identity. Pattern *source → interpretation → routing → promotion → reinterpretation* mirrors clinical *source → observation → assertion → adoption → action*. (Open Q §4.6 still governs which members are reservoirs vs domain-memory vs projection.)

## 4. Open questions that need DEFINITION, not just names (do not answer tonight)

1. **Care Outcomes Learning system** — what does it actually look like? Sub-sections? **Does marketing-outcomes learning live there, or separately? Only care decisions? Ops decisions too?** Is "learning from OMNI's own actions" ONE reservoir or several (care vs marketing vs ops outcomes)? This is the "100,000 clinical decisions OMNI acted on and learns from" question — *the name for that part of the build is currently missing.*
2. **Clinical Memory's class** — is it a member of this family, or inherently substrate/domain truth (and only *consulted* by the family)? Its authority is patient-specific truth, far above outside reference. Where is the boundary between Clinical Memory (patient truth) vs Medical Literature (general knowledge) vs Care Outcomes Learning (system learning)?
3. **The CNS framework itself** — how does it assemble context (context packets), draw on reservoirs, route, draft, escalate? Are there "hemispheres / regions"? Where do the learning loops live? OMNI has no CNS framework comparable to its surface/substrate definition. (Builds on the existing `contracts/CNS_orchestration_contract.md`, but that does not yet carry the reservoir-family + context-assembly + learning-loop taxonomy.)
4. **Final family name** (see §1).
5. **Authority-class taxonomy** — enumerate the classes and their use/care boundaries.
6. **Reservoir vs domain-memory vs projection/read-model vs processing-workbench** — what distinguishes a *reservoir* from a *domain memory* (Clinical Memory = patient truth, P1), a *derived projection/read-model* (a RAG index, P4 — projection ≠ truth, §7.7), and a *processing workbench* (the Evidence Plane)? **Clinical Memory, Evidence Plane, RAG projections, and Care Outcomes Learning must NOT collapse into one thing.** This distinction will matter a lot — it likely determines which of these are even "reservoirs" vs members of other planes the CNS merely consults.
