## §4 HEADLINE CROSS-CUTTING FINDING — the governed decision/resolution primitive (ROUTE-OUT to v4; bigger than C3.7, and bigger than "clinical")
C3.7's `honest_null_terminal` is revealed as the **oncology-trial-access subtype** of a 3-level hierarchy (Nick + Knox + Opus, 2026-06-14). **Do NOT prematurely crown `clinical_decision_state` as the top primitive.**
- **PARENT (cross-substrate, name TBD in v4): `governed_decision_lifecycle` / `action_resolution_state`** — how ANY recognized problem/signal/request/candidate-action is resolved: act · defer · monitor · consult/co-manage · escalate-if-fails · no-action · patient-declined · disputed · pending · superseded · outcome-tested. Spans clinical, research-match, billing/coding, operational-routing, escalation, visibility/access, policy-exception decisions.
- **CLINICAL CHILD: `clinical_decision_state`** (Nick's name) — the care specialization (treat/monitor/defer/consult/no-intervention/escalate-if-fails/declined/preserve-option/uncertain).
- **C3.7 SUBTYPE: `honest_null_terminal`** — no-appropriate-trial / SOC-better / palliative-honest / not-eligible-now-standing-match-later.

**Opus strengthenings (push past "just name a bigger parent"):**
1. **This is the COMPLETION of C3.5's Chain A act-loop, not a brand-new primitive.** C3.5 G4 §5 named the canonical loop `signal → candidate → authority-gate → act/event → proof → obligation → learn` — but that only models the **"act" branch.** The parent here adds the missing **non-act / defer / dispute / uncertain / outcome branches.** Frame it as "Chain A was under-specified," which grounds it in canon instead of floating a new top-level object.
2. **PATTERN vs OBJECT — avoid the god-object (the inverse of domain-explosion).** The parent is most likely a **canonical pattern/law (like Chain A) + domain-specialized records**, NOT one universal owned object. The *shape* generalizes; the *governance* (who may commit a "no", evidence, reopen-triggers, patient-explanation) is domain-specific. A single universal `governed_decision_lifecycle` object would become a god-object. **Key reconciliation question: pattern or object?**
3. **Separate the RECORD from the LIFECYCLE.** The durable governed *record* ("problem/candidate → stance → by-whom/why → reopen-triggers → later-outcome") is a truth-plane object (CM/D7/CNS); the *lifecycle* is the state-machine CNS orchestrates. Splitting them answers Knox's "which contract owns the canonical record" cleanly: record-owner ≠ process-orchestrator.
4. **Outcome-testable WITHOUT retroactive judgment.** The record must freeze what-was-known-then (immutable decision-context) and link a later outcome read by `outcome_intelligence` — mirroring C3.6 amend-not-overwrite + source-authority. Reasoning-quality ≠ decision-correctness; M&M/peer-review is a downstream consumer, not a field.
- **Definition:** a governed state representing *how a recognized clinical problem / request / diagnostic assertion / candidate action is being managed when the answer is not simply "do the action now."* Covers: treat-now · monitor/watch · defer-pending-data · defer-to-specialist · consult/co-manage · escalate-if-first-line-fails · **no-intervention/not-indicated** · not-owned-by-this-service · patient-declined · preserve-downstream-option · carry-as-diagnostic-uncertainty.
- **The law:** **Recognition ≠ ownership ≠ action ≠ intervention; non-action can be the correct committed care decision.** An action substrate that records only "yes/do-it" is a conversion machine.
- **Three required dimensions (ONE primitive family — do NOT mint three objects):**
  1. **Stance** (the list above) + fields: `problem_or_question · diagnostic_assertion_status · requested_or_considered_action · stance · owning_actor · authority_gate · rationale · evidence_basis · uncertainty_level · patient_explanation · follow_up_obligation · reopen_triggers · audit_trace`.
  2. **Decision lineage across actors + time** (the genuinely novel part C3.5 lacked): a chain of stances on the SAME problem — surgeon-A-says-no → surgeon-B-says-yes → conditions-unchanged-so-now → "the last team punted; still time now." *Non-change is itself a reopen trigger.* Inter-actor attribution; previous-provider-said-no/I-say-yes (also in async/Hims, cardio/onc group practice).
  3. **Honest rationale-class** (makes grey-zone medicine legible without lying or auto-judging): clinical-optimal · patient-preference · disposition/system-constraint (e.g. wait-for-rehab-qualification) · futility-but-values · defensive · resource/access-driven · uncertainty/watchful. **Ties to the firewall:** rationale-class is how OMNI distinguishes an honest disposition-driven tradeoff from revenue/incentive masquerading as clinical.
- **Disposition:** **ROUTE-OUT to v4 / general ACTION substrate** for a focused **Decision-State Reconciliation Pass** (a small reconciliation, NOT a scenario batch) across CNS · Clinical Memory · OFC · D5/`care_state_view` · RBAC · D7 · Messaging/Surfaces · `outcome_intelligence`. **Do NOT assume CNS alone owns it; do NOT mint a C3.7-specific object; do NOT mint `recommendation_discordance` separately** (composes under the lineage dimension + downstream `outcome_intelligence`). C3.7 keeps ONLY the trial-access subtype. **Serious `08`/C4 open-review item, not a side note.**
- **Reconciliation-pass questions (for v4):** parent = pattern or object? · which contract owns the canonical *record* (vs which orchestrates the *lifecycle*)? · relation to `cns_decision` / `clinical_assertion` / `care_obligation` / `care_state_view` / `outcome_intelligence`? · how are disagreement / uncertainty / non-action / deferral / outcome-feedback represented? · patient-facing explanation? · is it the completion of Chain A?
- **The law to preserve (v4):** *a mature action substrate models not only actions, but stances, deferrals, disagreements, non-actions, uncertainty, reopen-triggers, and later outcome pressure.* Recognition ≠ ownership ≠ action ≠ intervention.
