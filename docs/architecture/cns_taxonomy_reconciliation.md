# CNS taxonomy reconciliation — cross-surface map (DL-16 binding)

**Status:** companion reference, not binding doctrine. Bound by **DL-14** (OMNI CNS center of gravity), **DL-16** (universal CNS event envelope + taxonomy evolution), **ADR §7.17**, and **ADR §7.19**. Read this when implementing a new domain integration, registering a new `event_kind` in the taxonomy registry, or auditing whether an existing surface's event vocabulary cleanly partitions into DL-16's seven categories.

This document does NOT invent architecture. It is a **reconciliation table**: each row is an OMNI surface (a domain that produces and/or consumes CNS events); each column is one of the seven DL-16 vocabulary categories. The cells name representative `event_kinds` / `action_kinds` / canonical record types per surface per category, plus reconciliation notes (where the seam lives, what is committed vs reserved vs deferred).

The table is illustrative, not exhaustive. The authoritative source for active `event_kinds` + `action_kinds` is the **taxonomy registry** (per DL-16 invariants 5 + 9 + 29). When the registry and this document disagree, the registry wins — this document gets updated.

## §1 The seven DL-16 vocabulary categories (recap)

Per DL-16 invariant 3 (binding partition) and MAIN `§1Z.2`, every conceptual artifact in the CNS event graph belongs to exactly one of:

1. **Domain event** — a fact ABOUT THE REAL WORLD that has occurred (something happened in a sibling domain or external rail). Past tense, immutable, the CNS reads it.
2. **Canonical domain state** — the authoritative record table maintained by the sibling executor (the appointment row, the order row, the prescription row, the lab result row, the message row, etc.). NOT a CNS artifact directly; CNS reads through projections or source-of-truth queries per DL-16 invariant 24.
3. **Orchestration run** — a parent saga / multi-step pathway record (per DL-14 invariant 17). Models multi-action journeys (e.g., lifecycle nurture campaign, lab-result cancel-cascade, no-show recovery, peptide check-in sequence).
4. **Orchestration action** — a CNS-emitted INTENT to do something downstream (primitive #10). Single atomic emission. The CNS writes it; siblings execute it.
5. **Rail/surface projection** — a materialized view optimized for a specific UI or downstream consumer (inbox thread view, dashboard rollup, search index, patient timeline, provider task list). NEVER authority per DL-16 invariant 19; rebuildable from canonical state + event stream.
6. **Outcome / feedback event** — a fact that an action either succeeded, failed, was suppressed, was overridden, was acknowledged by a human, was edited, was thumbed up/down. The CNS reads outcomes to update its world model + power learning loops per DL-14 invariants 6 + 22.
7. **CNS decision** — a first-class audit record per DL-16 invariant 30. Captures WHICH event(s) triggered, WHICH context was assembled, WHICH rules / AI envelopes / policy layers resolved, WHICH alternatives were rejected, WHICH action(s) were emitted (or why no action). Distinct from events, runs, actions, and outcomes.

## §3 Reconciliation patterns observed across surfaces

Reading across the table, several patterns repeat:

1. **Bidirectional seam is universal.** Every surface row has both column (1) [events PRODUCED] and column (4) [actions CONSUMED]. None is unidirectional. DL-16 invariant 4 binding holds: every domain integration is bidirectional.

2. **Canonical state stays in the sibling, never in CNS.** Column (2) is owned by the surface executor, not by the CNS. CNS reads through source-of-truth queries (DL-16 inv 24) or projections (column (5)); CNS never replicates canonical state inside itself. DL-14 invariant 16 + DL-16 invariant 6 + invariant 24 hold across all 20 rows.

3. **Projections are NEVER authority.** Column (5) is rebuildable per DL-16 inv 19. Clinical-decision surfaces read column (2) directly per DL-16 inv 24. Search index reads (row 18) are the canonical example of projection-only-never-authority.

4. **Compensation, not silent rollback.** Column (6) outcome events are facts about success/failure/correction. When an action fails or was incorrect, the recovery is a NEW orchestration_action emitted (a compensating action — correction, cancellation, refund, supersession, apology) — never silent state revert. DL-16 inv 31 holds.

5. **Decision records (column 7) are first-class.** Every surface row has its own CNS decision records — the audit trail of WHICH events triggered the decision, WHICH context was assembled, WHICH alternatives were rejected, WHICH actions were emitted. DL-16 inv 30 binding holds.

6. **Multi-step journeys live on orchestration_runs.** Column (3) is the parent saga. Single-emission actions live on column (4) (orchestration_actions). The two are distinct row types per DL-14 invariant 17.

7. **Universal envelope inherited by every event_kind in column (1) or (6).** Every domain event AND every outcome event in this table carries the DL-16 envelope per invariant 2 — `event_id`, `event_kind`, `domain`, `source`, `actor`, four time fields, `entity_refs`, `before_state`, `after_state`, `payload_version`, `schema_version`, `audit_lineage`, `idempotency_key`, `confidence`, `correlation_id`, `causation_id`, `aggregate_id`, `sequence_number`, `tenant_id`, `environment_context`, `replayability_flag`, `status`, `replacement_kind`, `retention_class`, `consistency_tier`, `cost_attribution`.

8. **Vocabulary is extensible, NOT closed.** No row in this table is exhaustive. New `event_kinds` register through the taxonomy registry per DL-16 invariants 1 + 5 + 9 + 29. This document gets updated when the registry adds surfaces or kinds.

## §4 Anti-patterns this reconciliation catches (cross-link to radar zones 114-131)

Reading this table catches concrete drift early:

- A row where column (1) and column (4) overlap (e.g., an `appointment_booked` listed under "actions the surface consumes" instead of "events the surface produces") — drift toward event/action conflation (radar zone 115).
- A row missing column (4) entirely — drift toward unidirectional CNS↔domain seam (radar zone 116).
- A row where column (2) overlaps with column (5) (canonical state reused as projection) — drift toward projection-as-authority for clinical-decision surfaces (radar zone 125).
- A row missing column (7) — drift toward missing CNS decision records (radar zone — DL-16 inv 30).
- A surface that proposes an event with raw PHI in payload (e.g., full chart context in an SMS-dispatched event) — drift toward PHI broadcast (radar zone 118; payload minimization DL-16 inv 7).
- A surface integration that proposes 2PC / distributed transactions across siblings — drift toward two-phase commit (radar zone 122; saga-only DL-16 inv 26).
- A surface whose `event_kind` enum is finite / hard-coded — drift toward closed taxonomy (radar zone 114).
